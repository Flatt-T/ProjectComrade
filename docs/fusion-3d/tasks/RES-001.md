## Procedure

1. Read the era matrix and current repository audit. Create one canonical released-product ledger with family, title, expansion/port/region/platform, release status, relationship to its parent and proposed inclusion disposition. Resolve names against the publisher collection release inventory and primary release announcements; label gaps pending rather than claiming the list is complete.
2. For each main PC game choose a precise retail/official-patch source profile, using the latest officially patched baseline only when evidence supports its identity. Preserve alternative editions as explicit deltas. Record version string, platform, language, official patch, file hashes, executable/build identifier where available, asset/config provenance and whether modifications are installed.
3. For live services, pin observation time, app build, region, season/world rules and data revision. A dated publisher announcement establishes an announcement, not present availability or an exhaustive current roster. Revalidate live status when the individual task executes.
4. Record source hierarchy: shipped-build measurements for active behavior; matching shipped configuration and active code; authored manuals with patch caveats; official SDK/reference data; primary contemporary statements; secondary discovery. Record legal access method and retrieval result. An archived official manual is primary-authored evidence on a secondary host.
5. Audit the four pinned source repositories and later-era XML release. Preserve both commit SHA and blob SHA; distinguish code release licence scope from retail content. List compile guards and build/profile mismatches that require active-retail reconciliation.
6. Assign an explicit disposition to console/mobile/FPS/browser/cancelled items: full core content, edition delta, adaptation study, reference-only, excluded inactive material, or unresolved. Exclusions need scope rationale and supervisor approval; no released source family may silently disappear.
7. Publish a denominator manifest by source profile and content category. Separate confirmed shipped objects, discovered candidates, aliases, inactive records, unclassified records and genuinely inaccessible evidence. The manifest must support later subtraction/reconciliation without rewriting historic IDs.
8. Obtain independent review of the scope manifest before declaring an era census complete. Open precise source-blocker records for missing versions/manuals rather than broad requests to redesign the project.

## Guardrails

- Treat this card as a bounded contract. Read the named context and dependency outputs first. If required evidence is missing, record a precise blocked datum and continue only with independent work; never fill a field with an assumed zero, a plausible remembered value, or another era's value.
- Preserve native Classic fidelity independently from source-era research profiles and the newly authored Fusion rules. A Fusion change is an explicit adaptation decision with rationale and acceptance tests, never a retroactive claim about the historical game.
- Cite each nontrivial historical statement or numeric datum to an exact manual page, immutable source path/line or symbol, or timestamped observation in an identified shipped build. Search snippets, fan wikis, source declarations and official announcement text cannot alone prove shipped behavior.
- Keep code licence, trademarks, audiovisual assets, music, voice, map files and gameplay research as separate provenance questions. Do not redistribute retail game files or copied art/audio in the repository; original homage assets or specifically permitted material need their own provenance record.

- Write factual conclusions, calculations, test setup, results and concise decision rationale. No private reasoning trace is required. Spend available analysis on the assigned bounded task; do not inflate output or exceed the context window merely to claim exhaustive thought.
