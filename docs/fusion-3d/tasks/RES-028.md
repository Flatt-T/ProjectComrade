## Procedure

1. Read all reference manifests, era reconciliations, schema, capability contracts and approved Fusion dispositions. Refuse to generate release-ready entity tasks from unresolved aliases, inactive source records or unverified file paths.
2. Compute denominators by source profile, faction, entity category and implementation disposition. Reconcile all discovered candidates into confirmed included, inherited alias, inactive, excluded with approval or unresolved. Publish unresolved counts; never hide them in a percentage.
3. Supply validated source identity rows to OPS-005, the sole canonical generator/publication owner. Use F3D-ENTITY-<rowUid>-<stage>-<part>, where rowUid is SHA256 of RES-003 canonical immutable identity prefix16 with full hash retained and collision failure. Require canonical stages SPEC, SIM, MODEL, RIG, ANIM, FX_AUDIO_UI, INTEGRATE and REVIEW. ART-013 expands/validates asset stages only; no independent research or asset upsert is permitted.
4. Each task must include exact source and Fusion profile values, capability prerequisites, relevant context files, permitted edit paths, non-goals, input/output schemas, procedure, acceptance fixtures, assets/provenance requirements and handoff. Resolve links to concrete evidence and prior issue records where available.
5. Split work so a leaf contains one complex entity or at most five simple related variants; use separate intake batches for raw records. A task cannot span an entire game or ask a small agent to infer the missing reference context. Shared assets/modules may be referenced only after a reviewed sharing decision.
6. Validate canonical dependencies: approved SPEC and capability support before SIM; art style/geometry contract before MODEL; approved RIG/state contract before ANIM; rights/provenance before distributable assets. INTEGRATE requires applicable SIM, MODEL, RIG, ANIM and FX_AUDIO_UI outputs. REVIEW requires actual SIM, FX_AUDIO_UI and INTEGRATE evidence and independent review; asset completion alone cannot close it.
7. Dry-run graph generation and validate no cycles, duplicates, missing entities, missing stages, dangling source references or forbidden phase bypass. Re-run with the same inputs and confirm identical stable task identity and dependencies. Reconcile with existing GitHub/Linear IDs through the supervisor rather than creating duplicates.
8. Produce delivery gates by era/faction and a cross-era integration matrix. Research complete, logic complete, art complete, animated, integrated and release-accepted are separate statuses; no one stage automatically completes the others.
9. Deliver the whole-census reconciliation and dry-run change manifest for independent RES-029 audit. OPS-005 owns issue creation/ID mapping; accepted seed and era batches may already have been published under their own independent review. This task does not wait for its downstream RES-029 audit to complete itself.

- Every verified included entity has all required stages or a reviewed shared-stage reference; every omitted candidate has an explicit classified reason.

- Unsupported capabilities and unresolved rights/specification fields create exact blocking dependencies rather than placeholder success.
- Existing issue mappings can be applied without changing entity identity or duplicating tasks.
- Completion report uses separate observed/discovered/verified/built/animated/integrated/accepted counts and never equates raw inventory counts with playable completion.

- The artefacts are machine-parseable where specified, use stable IDs, contain no unresolved placeholder text disguised as final data, and have an independent reviewer assigned.
