## Procedure

1. Read the locked reference manifest and catalogue schema. Confirm an exact legally accessible source profile, source/config hash and observation environment before extracting facts. 2. As this is an era work package, first generate bounded research leaves: one faction availability/production graph, at most 25 simple raw-definition classifications per intake leaf, and one complex entity or at most five closely related simple entities per behavior-evidence leaf. Give each leaf the relevant source excerpt/locator, profile, output schema, acceptance and reviewer. A coordinator must not claim an entire era was completed in one context window.
3. Create an unfiltered candidate census from active source/config enumerations, manuals, mission references and map object lists. Preserve raw IDs; classify buildable units, buildings/defenses, walls/gates, neutral tech/civilian objects, heroes, campaign-only units, support powers, upgrades, deployed/transformed forms, summoned/spawned children, projectiles, wrecks, unused/cancelled records and visual-only helpers.
4. Extract full faction availability and production graphs, including prerequisites, negative restrictions, expansion inheritance, capture access, tech upgrades, per-mode legality and one-per-player restrictions. Record economy/build timing, mobility/target layers and every signature interaction with source evidence.
5. Create a pinned Yuri expansion overlay over RA2. Reconcile inherited country roster, modified values, removed/replaced definitions, new Allied/Soviet entities and the complete Yuri production/economy/defense/support tree.
6. Verify expansion additions such as Guardian GI, Battle Fortress, Siege Chopper, Boris and Robot Tank from active production rather than blended franchise memory. Catalogue Yuri infantry, ground/naval/air units, structures, defensive buildings and powers independently.
7. Observe Slave Miner deploy/move/slave generation/harvest/death/capture; Bio Reactor occupant power; Grinder recovery; magnetron lift/drop interactions; mind control slots, Mastermind overload and release; gatling spin states; genetic mutation; floating disc draining; force shield and psychic dominator behavior.
8. Create exact transport/loadout records, including Battle Fortress firing passengers and IFV variants, plus target immunity and ownership-loss edge cases. Do not implement Yuri mind control as a simple damage number or visual effect.
9. Record lunar campaign units, terrain, movement and availability; campaign-specific hero/civilian/secret-lab results; and any truly new terrain sets. Determine whether each extra is a campaign mode, optional authored content or general buildable Fusion entity.
10. Retain original RA2 profiles for historical comparison; expansion corrections must not overwrite base values without an explicit profile relation.
11. For each behavior-critical entity create a repeatable observation fixture with initial state, input sequence, measured outcome, units/tolerance and video or event evidence where available. Measure movement/turning, acquisition/firing/reload, health/armor/damage, costs/build times, special ability state and death/ownership transitions. Unknown values remain explicit blockers for that entity.
12. Document geometry, silhouette, material, faction cues, required animation states, effects, audio and destruction as observable reference requirements; list original-asset production needs and distinct permission/provenance records. No sprite recolor or generic primitive may be counted as the final full-3D model.
13. Create a theatre/terrain/props register and terrain-mechanic matrix from shipped maps/assets. Record which bridges/ice/tunnels/water/cliffs/buildability/destructibles actually exist and which rules are still unverified. Route bridge/world features to RES-025 with exact map/build evidence.
14. Create a source-to-Fusion disposition for every entity and mechanic: faithful profile, authored adaptation proposal, campaign/scenario-only, reference-only, verified inactive alias/exclusion, or unresolved. Unsupported engine capabilities block affected entities; do not fake them with a generic unit type.
15. Reconcile candidate counts to final categories and compare manual roster, active definitions, producer menus and campaign/map references. Explain every discrepancy, alias and exclusion. Submit complete era package for independent review and emit the downstream per-entity implementation draft only from verified included records.
