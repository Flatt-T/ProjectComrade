## Procedure

1. Pin the first-battle seed to verified RA1 Allied/Soviet reference profiles from RES-005 plus explicitly cited bridge observations. Enumerate exact source rows before accepting downstream values; this manifest is the bounded denominator, not an invented final roster. Required seed coverage: RA1 Allied/Soviet reference identities, explicit Fusion bridge reconstruction and protection policy, selected source unit/structure IDs, resource/tech/action values, scale/time translations and persistent eligibility boundaries.
2. Read source-era capability conflicts, terrain/bridge evidence, feel benchmarks and the current MMO requirements. Separate native Classic, reference era profiles, authored Fusion tactical mode and persistent-world orchestration in every decision.
3. Choose a documented representation for each faction/country/general/class and each content category. Preserve distinctive build/tech/economy restrictions or record deliberate adaptations; do not turn every faction into access to every unit.
4. Resolve tactical resource interoperability, technology progression, production concurrency, unit caps, superweapon cadence, damage/armor domains, range/scale/animation timing and terrain layers. Specify conversion rules, their purpose and balance hypotheses while retaining historical values unchanged in source records.
5. Define cross-era high-risk interactions: mind control versus heroes/epics/crawlers; EMP/shields/chrono/freeze/teleport; water/air/subterranean transforms; carrier/spawn children; engineer capture; garrison/transport and salvage; bridge destruction under mixed movement layers. Explicitly classify supported, blocked and intentionally immune cases with rationale.
6. Keep the latest user alliance/occupation contract: allied Engineers may capture allied structures only with consent; enemy capture checks shield eligibility; offline shield prevents new entry; allied units already stationed remain protected. Link tactical capture/repair actions to world-authority eligibility without rewriting Classic rules.
7. Create authored Fusion bridge reconstruction policy using RES-025 evidence and world team design: states, segment topology, repair actor/site/cost/time/ownership, occupancy/falling consequences, passage below, debris, synchronization and interruption. Label this policy new design, not universal historical C&C behavior.
8. Assign every campaign/FPS/browser/mobile mechanic a deliberate transfer disposition with context: fully integrated, scenario/optional mode, visual/content adaptation, world-layer reference, explicit excluded mode or evidence-blocked. All released content remains accounted for in the ledger even when its original control mode is not implemented.
9. Create a first playable integration slice that proves representative distinctive mechanics, full 3D/animation and bridge rebuild before scaling content. Specify what each later era delivery gate must show; no arbitrary priority choice may erase the eventual full content obligation.
10. Submit decisions to engine, world/art, AI, QA and product oversight. Publish approved/default/tentative statuses separately, with rollback/profile migration effects and exact downstream task blockers.
11. Produce an extension manifest for every remaining era/faction/capability/theatre/feel/adaptation row, with responsible source/PKG owner, required evidence and bounded follow-up work. Global reconciliation belongs to RES-028/029; no absent era is silently omitted or marked complete here.
