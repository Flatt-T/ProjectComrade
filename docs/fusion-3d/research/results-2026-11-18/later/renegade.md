# Renegade research for the unified homage

The game manual describes a team economy coupled to intact buildings and purchases from linked terminals. GDI and Nod field different structures/interiors, weapon presentation, defensive silhouettes and purchase menus. A selection on a terminal can depend on another building across the base. For a Fusion adaptation, keep that dependency and its feedback visible from tactical zoom. The [Renegade manual, Command & Conquer Mode section](https://gamepedia.cursecdn.com/cnc_gamepedia_en/c/cd/Renegade_-_English.pdf?version=a080e5c0939b482517e097f5087def99) and [EA recovered source](https://github.com/electronicarts/CnC_Renegade/tree/3e00c3a1b97381bb28be89a35b856375e0629a08) supply independent data and behavior anchors.

## Map evidence and visual direction

The public EA materials contain **10 multiplayer and 13 single-player LVL files**. The [map marker index](renegade-map-markers.json) pins the blob for each and indexes matching ASCII strings with exact offsets. The extraction restricts names to selected multiplayer preset/terminal patterns. It found **222 distinct labels across 6,966 matching occurrences**. These are references found in editor-level bytes. A string can describe a label, nested preset, script or inactive item. It does not establish an active placed object, collision bounds, a census of equipment or a mesh license.

For the Field multiplayer map, the data exposes `mp_GDI_Barracks`, `mp_GDI_War_Factory`, `mp_GDI_Refinery`, `mp_GDI_Advanced_Guard_Tower`, `mp_Hand_of_Nod`, `mp_Nod_Airstrip`, `mp_Nod_Refinery`, `mp_Nod_Obelisk` and both team's terminal-zone labels. Use this map as a reference set for silhouettes, faction recognition and battle functional roles. Test with the two starting camera orientations; measure entrance and terminal visibility in intact, damaged and disabled states. [Official level evidence](https://github.com/electronicarts/CnC_Modding_Support/blob/3aad8e412961ab543192ae70f8503dc8e178e095/Renegade/Maps/Multiplayer/C%26C_FIELD.LVL)

Full purchased presets, meshes, character variant values and per-map active placements still require the corresponding rights-cleared retail data/version and observation. The recovered code defines data readers and access patterns; the inspected code archive does not include an objects.ddb or complete preset-price roster. Preserve map-specific availability and differing character classes/weapon sets as explicit research rows. Do not infer a playable vehicle from an opaque numeric level ID or transfer the native first-person mode’s entire physics/input model into Fusion.

## Westwood multiplayer demo 1.019 purchase terminal

The February 2002 demo is independently identifiable from two mirrors. The 96,216,130-byte self-extracting installer has SHA-256 `a4f42065491f30fe969739abdd88e6169618b3790d8401871453caa66964024f`. Its own `README.HTM`, menu screenshots, binary object definitions, English string database, default server settings and Under map are part of the same package. [Demo listing and download](https://cncnz.com/downloads/renegade-downloads/) · [Second archive listing](https://frag-net.com/game_renegade.html)

[The 73-row ledger](renegade-demo-terminal.tsv) joins every nonempty primary/alternate menu row from the demo’s global purchase settings to a preset ID, internal definition name, English slot label, texture identifier, configured cost, and an offset into the original settings database. It records zero-definition label-only rows, preserves shared names and leaves missing labels empty. Eight rows are alternate character presets sharing their parent’s slot price. The three different Nod specialists all display as Black Hand, and the two Sydney slots have distinct preset IDs. Key by team, mode, slot and preset ID when implementing this purchase screen.

The demo’s deployable roster requires care. Four aircraft-associated normal vehicle slots exist in the global settings; the supplied vehicle-menu images end at five GDI ground slots and six Nod ground slots. The visible GDI menu comprises Humm-Vee, APC, mobile rocket launcher, Medium Tank and Mammoth Tank. The visible Nod menu comprises Buggy, APC, Mobile Artillery, Flame Tank, Light Tank and Stealth Tank. Both included server profiles name C&C_Under.mix and set starting credits to zero. The extracted Under map's local DDB, LDD and LSD contain no purchase-settings chunks of the two decoded classes. These findings support the illustrated ground roster while leaving in-match order acceptance for the unillustrated aircraft, secret entries and alternates open.

Forty-three illustrated offers have independently read prices in the ledger. Twenty illustrated prices differ from the value stored in the corresponding binary slot. For instance GDI’s Humm-Vee is configured at 350 and pictured at 400, its rocket launcher is configured at 450 and pictured at 800, and its Mammoth Tank is 1,500 in both. Record edition, source channel and base-power state before choosing a reference price. The readme describes a destroyed power plant doubling character, vehicle and beacon prices. The whole discrepancy set cannot be explained by a single doubling factor. The included main-screen images show four free basic characters, free refill, character and vehicle submenus, and the faction beacon. Treat the delivered artwork as a locator for an authorized reviewer. Recreate original Fusion terminal graphics separately.

The [evidence record](renegade-demo-terminal-evidence.json) preserves the MIX offsets, hashes and screenshot member names. All 15 purchase-settings chunks are inventoried, including empty equipment and mutant settings. For reproducibility, run `python renegade_demo_purchases.py RENEGADEMULTIDEMO1019.EXE output_directory`. The [reader](renegade_demo_purchases.py) bounds-checks container chunks and follows the publisher’s slot, alternate, name and cost serialization. It separates capitalized-filename CRC lookup from the independent ID-to-translation join. ### Independent terminal reproduction

A clean rebuild from the CNCNZ mirror reproduced both the complete TSV and evidence JSON byte-for-byte. A separately downloaded copy from the [Games Domain archive mirror](https://ftpmirror1.infania.net/pub/gamesdomain/demos/renegadedemo_1019.exe) shared the same installer digest as both other sources. A [second reader](renegade_demo_verify.py) independently located all 15 settings chunks by their serialized identifiers and verified every row against their byte streams. It checked 73 unique row keys, all 70 nonzero preset ID/name joins, all 71 nonzero localization ID/English-label joins, 63 explicitly serialized credits values and the hashes of eight original readme, screenshot and map members. The 10 other credit entries are basic characters and refills, documented as free in the included material. The [verification receipt](renegade-demo-verification.json) identifies the exact TSV hash. To repeat it, run `python renegade_demo_verify.py second-demo-copy.exe output_directory verification.json`.
