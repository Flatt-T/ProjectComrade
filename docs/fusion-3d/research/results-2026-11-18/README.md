## Start one bounded implementation

A reproducible first integration target is the crossing on one map, behind the new Fusion profile. The renderer must show separate flows above and below the deck, allow picking by surface, close just the broken route on collapse, and reopen it once after a valid repair. Cover the contested engineer, replay and save/resume cases before extending to another bridge style. Use the original fixture to see what a breach should expose. Use the oracle to learn when the chosen Fusion rules reopen the route. Use the original game evidence to label which historical behavior informed the design. [Original geometry](art/bridge-study.gltf) · [Collision and pick measurements](art/bridge-study-verification.json) · [Transaction code](foundation/bridge_oracle.py)

For the production fleet, read the [task-by-task results](review/task-results.md) and the existing [Linear programme](https://linear.app/thunderchild-creative/issue/THU-2533). Pick a single dependency-ready entry. Attach the observed evidence, unknowns, work authorization and a falsifiable acceptance test to that specialist’s context. Re-run the input data and its negative control. An independent reviewer records the result before dependent work begins. The source census, visual production, rights review, performance testing and integrated game release each retain their own sign-off.

## How to verify a copy

Run `python review/verify_deposit.py` from an extracted copy. The [manifest](manifest.json) pins each delivered artifact by path, size, SHA-256 and Git blob ID. The verifier also checks nested factual archives and all 29 issue-to-file mappings. Original video imagery, games, installers and raw publisher data are referenced by location and hash. The rendered 3D studies were made for this project. [Independent historical and graphics checks](review/independent-acceptance.md) · [Video access record](video/source_access_status.json)
