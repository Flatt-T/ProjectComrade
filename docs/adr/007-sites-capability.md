# 007 — ChatGPT Sites capability assessment

Reviewed 25 November 2026 for [THU-1337](https://linear.app/thunderchild-creative/issue/THU-1337) against [COMRADE 09](https://linear.app/thunderchild-creative/document/comrade-09-hosting-chatgpt-sites-evaluation-operations-and-cost-model-516180d0bb47).

## Decision

Keep the browser client and the match and persistence services together on the portable HTTPS/WSS deployment. Comrade's service starts a Node HTTP server, handles WebSocket upgrades itself and supervises match workers. The persistent world connects to PostgreSQL and relies on leases, journal replay and checkpoints. The documented Sites Worker runtime has a different process model. A Site could be evaluated as a client in front of an external Comrade backend if the project later needs that split.

The connection for the selected Codex account returned a successful owner list with zero Sites. This proves that the account can reach the listing endpoint. Site creation, public publishing and custom-domain eligibility for this account and region remain unconfirmed. The current help article describes plan and workspace eligibility. It does not repeat the regional launch restriction quoted in the September plan. [OpenAI Help Center](https://help.openai.com/en/articles/20001339-creating-and-using-chatgpt-sites)

No Site was available for a private runtime check, and the ticket limits the assessment to work without live publication. The portable beta already provides same-origin HTTPS/WSS on its own domain. Changing its hosting would add an authentication and operational dependency while still requiring an external authoritative game service.
