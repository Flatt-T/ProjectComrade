## D. Routine implementation choices (executor's remit — recorded for reviewers)

| ID | Choice | Reason |
|---|---|---|
| DEC-IMPL-1 | New `mmo` schema inside the **separate beta database** `comrade_beta`, migrations embedded in the service following the `db.ts` `MIGRATIONS` convention. | Matches live conventions; keeps beta isolated per COMRADE 15. |
| DEC-IMPL-2 | Persistent-mode protocol `comrade.mmo.v1` on a separate WSS route (`/ws/mmo/` proposed); classic `/ws` untouched. | COMRADE 14 §5; avoids contaminating classic lockstep. |
| DEC-IMPL-3 | Region tick = the Fusion `Game.step()` at 15 Hz; journal entries carry `simulation_tick` + `event_seq` (bigint, decimal strings on wire per COMRADE 14 §5). | Reuses proven determinism; wire-safe counters. |
| DEC-IMPL-4 | First region uses an existing classic pack (`td` or `ra1`) under a new `persistent` rules profile, not a new pack. | Smallest real engine surface; profile carries all COMRADE 18 pacing/protection values. |
| DEC-IMPL-5 | Region hibernation accrual uses the region's measured recent harvest rate persisted at each checkpoint, capped by storage. | COMRADE 18 §2.3 exact wording; avoids inventing a constant income formula. |
| DEC-IMPL-6 | Notifications milestone-1 subset: in-app + web push placeholders behind opt-in flag; SES email reuse evaluated at PW25 (existing `ops`/SES setup is Classic-side; verify before relying on it). | COMRADE 18 §3.10; email path must not be assumed until inspected. |
| DEC-IMPL-7 | Standard lockstep matches: a dropped commander keeps their seat for **120 s** (`MATCH_RESUME_GRACE_MS`). The relay fills their turns with empty `synthetic` packets so nobody stalls; the room buffers relayed turns (`turnLog`, ≤50 k entries) and replays them on resume with `heldUntil` marking the boundary — the rejoining client drains the backlog at CPU speed and sends empty commands for held turns so state stays identical everywhere. Surrender fires only after grace expiry. | Warm rejoin must not stall real-time lockstep; 120 s covers browser sleep/network blips without pinning a slot indefinitely; all values service-side constants, not rules-profile (standard mode). |
| DEC-IMPL-8 | Rejoin is **warm-only**: the same tab must survive (resume token in sessionStorage). A cold browser restart cannot rebuild mid-match sim state — there is no snapshot distribution for standard matches yet — so it still surrenders after grace. Snapshot-based cold rejoin is recorded as a known limitation, candidate for a later issue. | Honest scope: turn replay restores determinism only for a live session; fabricating state would violate lockstep integrity. |
| DEC-IMPL-9 | Caretaker while offline (COMRADE 18 �3.1): an absent player's sim slot stays `connected` � no `leave` command is issued on socket drop � so standing orders (guard posts, attack-move routes, harvest loops, queued production, repair) keep executing under the normal sim rules. The client cannot issue new orders without a socket, so "never spends on new orders, trades, moves armies or attacks" holds by construction. Auto-repair stays a per-owner toggle to be added with PW11+; no autonomous purchasing is introduced. | Offline players keep last orders only; no new spending without a live session. |
| DEC-IMPL-10 | Fog of war in beta is **render-side only**: the snapshot necessarily contains full engine state and the deterministic sim needs it; a modified client can read hidden units. This is the accepted beta posture behind `decisions.fog_security = 'open'` (DEC-OPEN-4); if the owner requires server-side fog filtering before wider release, it lands as a config-gated layer, not a protocol change. | Beta honesty over false security; flagged in every snapshot's world config. |
| DEC-IMPL-11 | Region entry for beta is URL-driven (`/world?region=<uuid>`); there is no region picker/lobby yet. Region ids come from provisioning (PW09+). The `/mmo` gateway provisions a durable `player` row for any verified guest/account identity on first subscribe and joins it to the region's world. | Smallest honest entry path; picker arrives with world-map work (PW26/PW27). |
| DEC-IMPL-12 | Hibernation mechanics (PW22): quiescence is checked on a poll (`hibernatePollMs`, default 5 s) while the region is `active`; sleep requires no deliberate unit order (idle/harvest/guard-compatible), no armed entity with an enemy inside weapon range, no pending journal input and no scheduled job due within `inboundLookaheadMs` (default 120 s). Sleep writes a snapshot carrying `hib` metadata (wall anchor, sim tick, per-slot measured harvest rates), releases the authority lease and marks the region `quiescent`; the step timer stops. Wake (poller seeing in-window work, new worker start, or job due) journals a single `accrual` event whose payload carries rates+ticks; `Game.fastForwardQuiescent` advances production queues and harvest accrual arithmetically with the same storage caps/income bonus as live ticks, then the wall clock re-anchors so real-time stepping resumes. Exactly-once: the accrual event is journaled+applied in one transaction, and restore re-applies the slept interval whenever snapshot `hib` metadata is present even if the event row is already `applied` - a crash between apply and checkpoint neither loses nor double-applies it. `hibernateMinAwakeMs` (default 300 s) prevents thrash. | look-ahead 120 s, min-awake 300 s, poll 5 s (rules-profile tunables) | PW22 |
